# Backend: FastAPI API (Python 3.11 in Docker)

- Runs on `python:3.11-slim` (pinned by digest in `backend/Dockerfile`); the host has 3.12, so avoid 3.12-only syntax (for example same-quote nesting inside f-strings). Dependencies are pinned in `backend/requirements.txt` (including `httpx`, the outbound HTTP client, also used by the tests' `TestClient` and `httpx.MockTransport`); dev/test-only deps (pytest, pytest-cov, ruff, mypy) are in `backend/requirements-dev.txt`, layered on top (`-r requirements.txt` first). Tool config (ruff, mypy strict, pytest, coverage) lives in `backend/pyproject.toml`.
- Layout: `src/main.py` is only `app = create_app()` (uvicorn target `src.main:app`); `src/app.py` is the factory (logging, middleware, error handlers, routers); `src/routes/` holds one router per feature; `src/core/` holds config, schemas, errors, logging, middleware, plus the shared feature plumbing (`clock.py`, `http.py` the one outbound client, `snapshot.py`, `refresh.py`); `src/feed/` is the social feed package; `src/deps.py` the `Depends` seams (handlers read `request.app.state.settings`, never a module global).
- Routes: `GET|HEAD /health` (internal — the container `HEALTHCHECK` and the proxy network use it) and `GET|HEAD /api/health` (routed publicly by nginx, read by the uptime monitor) both return `{"status", "service": "yuriodev-api", "environment", "revision"}` — `environment`/`revision` come from `Settings` and prove what's actually deployed. Every error the app answers itself (404/405/422/500) is `{"error", "message", "request_id"}`, never input or a traceback. `GET|HEAD /api/posts` is the social feed (next bullet). Known gap: a 405 on the health paths says `Allow: GET` although HEAD is served (separate routes; Starlette names the first match). OpenAPI/Swagger exist only with `API_DOCS_ENABLED=true`, under `/api/openapi.json` and `/api/docs` (meant for dev; the Swagger UI assets are pinned to an exact `swagger-ui-dist` version in `src/app.py`); ReDoc is always off.
- Social feed, `GET|HEAD /api/posts` (ships **off**): `{version: 1, enabled, generated_at, source: {provider: typefully|fixture|none, status: fresh|stale|error|disabled, last_success_at}, items[]}`, one item per Typefully draft with per-platform `variants` (`x`: thread parts, `linkedin`: text) and permalinks; `Cache-Control: public, max-age=300`, a weak `ETag` over items + status, `304` on `If-None-Match`. Always 200/304: off gives `enabled: false, items: []`, upstream trouble only changes `source.status`, and the route only reads memory (visitors can never trigger a Typefully call). Code: `src/feed/` — `normalize.py` is the only place raw drafts become models (strict allow-list; `extra="forbid"` models in `schemas.py`; styled Unicode kept verbatim, no NFKC; control/bidi characters stripped; paid partnerships, the X side of subscriber-only posts, LinkedIn reshares and X Articles dropped), `providers/typefully.py` (one listing page of up to 50 published drafts, `get_draft?exclude_comment_markers=true` only for new or changed drafts, rate-limit headers honoured; the key is a `SecretStr`, sent per request, never logged), `providers/fixture.py` + `fixtures/drafts.json` (synthetic drafts for local/dev/stage, private fields hold `*-SENTINEL` strings), `curation.py` + `content/posts.toml` (pin/feature/hide by id and hand-added `[[native]]` posts; parsed strictly, shipped with commented examples only), `service.py` (incremental cycle, 30 min ±10% with exponential backoff, `fresh` within 2× the interval, `error` after `SOCIAL_FEED_MAX_STALE_HOURS`=72 without a success, when imported posts are withheld and curated ones kept; >50% invalid drafts keep the previous snapshot). The poller is a background task started in the lifespan only for `typefully`; startup and `/health` never wait on it. Settings (all off/empty by default): `SOCIAL_FEED_ENABLED`, `SOCIAL_FEED_PROVIDER` (`fixture`|`typefully`), `TYPEFULLY_SOCIAL_SET_ID`, `TYPEFULLY_API_KEY` (secret: `env/prod.secrets.env` only), `SOCIAL_FEED_REFRESH_SECONDS` (1800), `SOCIAL_FEED_MAX_ITEMS` (12), `SOCIAL_FEED_MAX_STALE_HOURS` (72), `SOCIAL_FEED_EXCLUDE_TAG` (`hide-from-site`), `SOCIAL_FEED_SNAPSHOT_PATH` (unset = memory only; the image has a writable `/app/data`). Turning it on is an env change plus a backend recreate, described in `deploy/README.md` ("Social feed"). `tests/test_feed_leak.py` proves no private draft field (scratchpad, title, tags, private/share URLs, media ids) reaches the body or the snapshot file: keep it green.
- Settings: `src/core/config.py` (pydantic-settings v2 `SettingsConfigDict(extra="ignore", env_ignore_empty=True, frozen=True)`, built lazily by the cached `get_settings()`; unknown env keys are tolerated, an empty value means "unset", and every field has a safe code default: no CORS, docs off, social feed off). `CORS_ORIGINS` (JSON list) adds the CORS middleware only when non-empty (no credentials, GET/HEAD/OPTIONS). `LOG_LEVEL` and `LOG_FORMAT` (`json` default, `console` for a local terminal) are applied at startup. Real config comes from the compose `env_file` chain (`env/<env>.env` then optional `env/<env>.secrets.env`) (the old `backend/.env` was retired on 2026-09-24). Never read any `env/*.secrets.env`; use `env/secrets.env.example` for variable names.
- Logging: `src/core/logging.py`, stdlib only, to stdout (Docker's json-file driver is the store; nothing is written to disk): one ASCII-only JSON object per line with `timestamp`, `level`, `logger`, `message`, `request_id` plus `extra=` fields (`LOG_FORMAT=console` escapes control, bidi and ANSI characters instead). `src/core/middleware.py` sets/echoes `X-Request-ID` and logs one `http.request` line per request (method, path, status, duration_ms, cf_ray) with no client IP, user agent or query string; `/health` lines only show at DEBUG. uvicorn runs with `--no-access-log --ws none` (its access log and its WebSocket handshake line would log the client address; there are no WebSocket routes) and its own loggers are routed through ours. No `print()`.
- Tests: `backend/tests/` (pytest; `conftest.py` has `make_settings`/`make_client`, which strip every Settings variable from the environment and build `create_app(Settings(_env_file=None, **overrides))`), so the suite passes with no env file and inside any `env/<env>.env` container; `test_main.py` is the one test that reads the real environment; `test_env_files.py` builds `Settings` from every tracked `env/<env>.env` (and fails on a `*_KEY`/`*_TOKEN`/`*_SECRET`/`*_PASSWORD` with a value), so a bad `LOG_LEVEL`/`LOG_FORMAT` fails CI instead of crash-looping the backend; it skips where `../env` is absent (the local dev container, or any run that has only `backend/`). `.github/workflows/ci.yml`'s `backend` job runs `ruff check`, `ruff format --check`, `mypy` and `python -m pytest -q --cov --cov-report=term-missing` (90% branch-coverage gate from `[tool.coverage]`; coverage is not in `addopts`, so a plain or subset `pytest` run is never failed by it; `filterwarnings = error`) with `requirements-dev.txt` installed, on Python 3.11, on every push to `master` and every PR. A host venv is impossible here (python3.12-venv missing, no sudo): run pytest in a throwaway `python:3.11-slim` container with `requirements-dev.txt` installed (see `/deploy-check`).
- The `runtime` image stage runs as non-root uid 10001 (user `app`, no shell/home) and installs only from the `builder` stage's prebuilt wheels (`--no-index --find-links=/wheels`, no compiler, no network); `wheel`, `setuptools` and the `jaraco.*`/`pkg_resources` packages setuptools vendors are uninstalled/removed afterward since they're fixable-CVE sources never needed at runtime (`pip` itself stays). `ARG GIT_SHA` (passed by CI) becomes `ENV REVISION`, which is what `/health` reports.
- Images are built in GitHub Actions, not on this box: `images.yml` builds the `runtime` target once per green `master` commit, scans it with Trivy (blocks on fixable HIGH/CRITICAL), and points `:dev` at it (and `:stage` while `STAGE_AUTO_PROMOTE=true`). A manual `docker compose build backend` here is break-glass only (see root `CLAUDE.md` golden rule 2).
- To see a change live before a release: push to `master`, then check `dev.yuriodev.co.uk/api/health` once the deploy agent (cron, within a minute) has recreated `yuriodev-dev-backend`. Its config is `env/dev.env` (+ optional `env/dev.secrets.env`) — never read the secrets file.
