# Frontend: React 19 + Vite 7 + TypeScript 5.9 (npm)

- Scripts (run in `frontend/`): `npm run dev` (vite on :5173; over SSH use VS Code port forwarding), `npm run build` (`tsc -b && vite build` -> `dist/`, gitignored), `npm run lint` (eslint 9 flat config), `npm run test` (`vitest run`; jsdom environment, `src/setupTests.ts`, see `App.test.tsx`), typecheck only: `npx tsc --noEmit -p tsconfig.app.json` (clean).
- `npm run lint` must stay at 0 problems: it blocks CI (and therefore image builds and every deploy). `npm run test` and `npm run build` block CI too.
- The build runs inside Docker (`npm ci` on node:22-alpine), so `package-lock.json` must stay in sync with `package.json`. Dependency changes (`npm install ...`) need Yurii's OK.
- Builds happen in GitHub Actions, not on this box: `.github/workflows/ci.yml`'s `frontend` job runs typecheck/lint/test/build/`npm audit --audit-level=high` on every pushed branch (except `production` and `dependabot/**`) and every PR, then `images.yml` builds the `runtime` target once per commit (pushed by digest, Trivy-scanned, tagged `sha-<commit>`/`dev-<commit>` only on a clean scan; an already-scanned commit is reused) and points `:stage` (`master`) or `:dev` (the repository owner's other branches) at it. A manual `docker compose build frontend` here is break-glass only (see root `CLAUDE.md` golden rule 2).
- No build-time config: the same `ghcr.io/...-frontend` image runs unmodified in dev/stage/production — nginx routing chooses the backend, not the build. There is currently no `import.meta.env.VITE_*` read anywhere in `src/`; keep it that way — anything that must differ per environment belongs in the backend's `/api/` response or in nginx, not baked into this image. `VITE_API_PROXY_TARGET` in `vite.config.ts` only steers the **Vite dev-server** proxy for `/api` (local/dev use), and is never read at build time.
- Local dev: on a Mac (never this box), `compose.local.yml` + the root `Makefile` (`make dev-up`) build this Dockerfile's `dev` target with HMR and bind mounts, `VITE_API_PROXY_TARGET` pointed at the local backend container. On this VPS there's no dev container; to see a change live before a release, push its branch: about 5-7 minutes later (CI incl. e2e, the image build, then the deploy agent's next minute) `dev.yuriodev.co.uk` runs it (the last build to finish wins; the terminal's `status` command shows it as `Branch:`; only the images change, nginx routing and the proxy config stay master's), and merging to `master` puts it on `stage.yuriodev.co.uk` the same way — both behind basic auth, credentials at `~/.config/yuriodev/basic-auth.txt` (never print them). Over SSH, `npm run dev` (Vite on :5173, port-forwarded) remains the fastest edit loop.
- Structure: `src/pages/*` compose `src/components/sections/*`; reusable widgets in `src/components/ui/*`; layout in `src/components/layout/*`. One CSS Module per component (`X/X.tsx` + `X/X.module.css`). Colours only through the CSS variables in `src/assets/styles/_variables.css`, with both `[data-theme="light"]` and `[data-theme="dark"]` variants. Font: Fira Code.
- Routes (react-router 7, `src/App.tsx`): `/` portfolio; `/community`, `/courses`, `/dashboard` are ComingSoon placeholders.
- API calls: none. The backend only exposes `GET /health` (and its public alias `GET /api/health`); there is no `/api/chat` or other business endpoint for the frontend to call.
- Dead files (don't extend): `community.html`, `courses.html`, `dashboard.html` (legacy multi-page entries), the 0-byte files in `public/`, `tmp/`, `generate_project_doc.py`, `show_docs_tree.sh`, `*.tsbuildinfo` at the frontend root.
